# 调试与构建配置说明

本文是本项目 VS Code 启动、调试、构建、打包与清理配置的统一说明。配置以 [.vscode/launch.json](../.vscode/launch.json)、[.vscode/tasks.json](../.vscode/tasks.json) 和 [package.json](../package.json) 为准；后续新增、重命名、调整或移除配置时，需在同一次修改中更新本文。

## 快速选择

| 你想做什么                                                   | 选择哪个入口                                                |
| ------------------------------------------------------------ | ----------------------------------------------------------- |
| 修改 React 界面、按钮交互或 Markdown 功能，同时检查本地逻辑  | F5 → **开发：完整调试（主进程 + 界面）**                    |
| 启动软件看看效果，或调试扫描、文件读写、原生菜单等主进程逻辑 | F5 → **开发：启动应用（F5）**                               |
| 为某个独立项目窗口设置界面断点                               | 先启动应用并打开项目，再选择 **开发：选择窗口（含工作台）** |
| 只检查类型并构建前端文件                                     | F5 → **构建：前端**                                         |
| 使用本地构建文件运行应用                                     | F5 → **运行：构建版**                                       |
| 生成当前系统与架构的安装包                                   | F5 → **打包：当前平台（安装包）**                           |
| 删除前端构建与本地安装包                                     | F5 → **清理：全部构建产物**                                 |
| 指定 macOS 双架构、Windows x64，或清理后再打包               | 终端 → 运行任务 → 选择对应任务                              |

## 首次使用

1. 在 VS Code 中打开本项目根目录，使 `.vscode/` 与 `package.json` 位于当前工作区根目录。
2. 安装 Node.js（版本要求见 `package.json` 的 `engines`），在终端运行 `npm install`。
3. 打开左侧「运行和调试」，从下拉菜单选择配置，按 `F5` 启动。

调试使用 VS Code 内置的 JavaScript 调试器，无需额外安装调试扩展。启动应用前会自动准备原生终端辅助程序、离线文件图标和 Vite 服务。

F5 菜单按 **01 开发调试 → 02 构建打包 → 03 清理产物** 分组。完整调试排在开发组首位；自动附加界面是组合配置内部使用的辅助项，不单独显示。

## F5 配置一览

### 开发调试

| 配置名称                            | 执行内容                                                                                                     | 结束方式                                                             |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| **开发：完整调试（主进程 + 界面）** | 同时启动「开发：启动应用（F5）」和「开发：自动附加界面」。可调试 Electron 主进程及 React / TypeScript 界面。 | 组合配置设置 `stopAll: true`，停止其中一个成员时会结束同组调试成员。 |
| **开发：启动应用（F5）**            | 先运行「开发：Vite」，就绪后启动 Electron，并调试主进程。                                                    | 应用进程退出或手动停止调试后结束。                                   |
| **开发：选择窗口（含工作台）**      | 连接已经启动的开发实例，列出可调试的界面窗口供选择。                                                         | 停止附加会话时结束；此配置本身不负责启动应用。                       |
| **开发：自动附加界面**              | 自动匹配本机开发页面，用于完整调试中的界面调试部分。此项默认隐藏。                                           | 作为组合成员随同组调试结束；也会在连接目标结束后断开。               |

**完整调试和启动应用的区别：** 两者启动的软件功能相同。「启动应用」提供主进程断点，例如 `electron/scanner.cjs`、`electron/project-files.cjs` 和原生菜单处理逻辑；「完整调试」额外连接界面调试器，可在 `src/*.tsx` 中检查按钮事件、组件状态和 Markdown 等界面逻辑。

独立项目工作台使用地址中的 `#project` 标识。需要指定某个工作台时，先在项目管理页启动该项目，再运行「开发：选择窗口（含工作台）」，选择对应地址的窗口。附加配置要求开发实例已开启 `9222` 调试端口，不能直接附加普通安装版。

macOS 中关闭窗口不一定退出应用；如果需要结束整个应用调试，可以使用应用菜单退出，或点击 VS Code 调试工具栏的停止按钮。

### 构建打包

| 配置名称                     | 执行内容                                                                      | 输出与结束方式                                                         |
| ---------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **构建：前端**               | 执行 `npm run build`：生成离线文件图标、检查 TypeScript，再由 Vite 构建前端。 | 输出到 `dist/`；命令进程结束后自动结束调试，不启动应用。               |
| **运行：构建版**             | 先运行「构建：前端」任务，再由 Electron 加载本地构建文件。                    | 使用 `dist/`，不依赖 Vite 开发服务；应用进程退出或手动停止后结束调试。 |
| **打包：当前平台（安装包）** | 执行 `npm run dist`，先构建前端，再由 electron-builder 为当前系统与架构打包。 | 输出到 `release/`；命令进程结束后自动结束调试。                        |

「运行：构建版」便于检查静态资源路径和构建后的行为，但不会生成或安装安装包，也不自动连接前端开发调试器。「打包：当前平台（安装包）」生成本地分发文件，不上传 GitHub、不发布 Release、不使用 GitHub Actions。

当前 macOS 打包目标为 DMG 与 ZIP，Windows 目标为 NSIS 安装器与 ZIP。需要同时生成 Apple Silicon 和 Intel 版本时，应使用任务菜单中的 macOS 双架构任务。

### 清理产物

**清理：全部构建产物** 直接运行 [scripts/clean.mjs](../scripts/clean.mjs)，效果与 `npm run clean` 相同：删除 `dist/` 和 `release/`，脚本退出后自动结束调试。

清理、构建和打包是一次性命令，不使用持续存在的“调试终端”会话。命令结束后终端会保留执行日志，这不代表调试仍在运行；如果命令失败，请检查终端中的错误和退出状态。

清理不会删除源码、`build/` 应用图标、`node_modules/`、文档、`artifacts/` 或 `.vscode/.user-data/`。`artifacts/` 存放自动化测试截图和失败现场，目前没有自动清理；确认截图不再需要排查或留存后，可以手动删除，后续测试会重新生成。

## 任务菜单一览

通过「终端 → 运行任务」选择以下任务。与 F5 调试会话不同，任务主要用于执行命令；其中「开发：Vite」是供开发调试复用的长期后台任务。

| 任务名称                                 | 对应命令或执行顺序                                       | 用途                                                                 |
| ---------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------- |
| **开发：Vite**                           | `npm run dev:renderer`                                   | 准备原生终端与文件图标后启动 Vite；就绪后允许 F5 继续启动 Electron。 |
| **构建：前端**                           | `npm run build`                                          | 生成 `dist/`，供构建版运行及后续打包使用。                           |
| **打包：当前平台（安装包）**             | `npm run dist`                                           | 当前系统与架构的安装包，也是默认构建任务。                           |
| **打包：当前平台（应用目录）**           | `npm run pack`                                           | 生成未制作安装器的应用目录。                                         |
| **打包：macOS（Apple Silicon + Intel）** | `npm run dist:mac`                                       | 为 arm64 与 x64 生成 DMG 和 ZIP。                                    |
| **打包：Windows（x64）**                 | `npm run dist:win`                                       | 生成 Windows x64 安装器与 ZIP。                                      |
| **清理并打包：当前平台（安装包）**       | 先「清理：全部构建产物」，再「打包：当前平台（安装包）」 | 使用 `dependsOrder: sequence`，清理成功后才继续打包。                |
| **清理：全部构建产物**                   | `npm run clean`                                          | 清理 `dist/` 和 `release/`。                                         |
| **清理：前端构建**                       | `npm run clean:dist`                                     | 只清理 `dist/`。                                                     |
| **清理：打包产物**                       | `npm run clean:release`                                  | 只清理 `release/`。                                                  |

按 `⇧⌘B`（macOS）或 `Ctrl+Shift+B`（Windows）会执行默认构建任务，即「打包：当前平台（安装包）」。清理前先结束正在运行的构建、打包或构建版应用，避免删除它们正在使用的文件。

停止 F5 调试后，Vite 后台任务会保留，供下一次调试复用。需要结束开发服务时，在「终端 → 终止任务」中选择「开发：Vite」。

## 端口、平台与设置位置

| 项目          | 当前配置                                       | 说明                                                               |
| ------------- | ---------------------------------------------- | ------------------------------------------------------------------ |
| Vite 地址     | `http://127.0.0.1:5173`                        | 使用固定端口，开发任务通过就绪日志判断服务是否可用。               |
| 界面调试端口  | `127.0.0.1:9222`                               | 由开发启动配置开启，供界面调试器连接。                             |
| 调试设置目录  | `.vscode/.user-data/`                          | 通过 `BKPM_USER_DATA` 指定，保存调试实例的设置与缓存，不提交 Git。 |
| 开发页面来源  | `ELECTRON_RENDERER_URL`                        | 开发配置指向 Vite，构建版配置设为空以加载本地 `dist/`。            |
| Electron 路径 | `node_modules/electron/dist/` 下的对应平台程序 | `osx` / `windows` 配置分别适配 macOS 和 Windows。                  |
| npm 执行程序  | macOS 使用 `npm`，Windows 使用 `npm.cmd`       | 用于 F5 的前端构建与当前平台打包命令。                             |

调试实例使用独立设置，不影响安装版的收藏、最近打开或外观设置。但如果选择同一个真实项目目录，Markdown 保存和终端命令仍操作该目录中的实际文件；测试写入行为时可使用示例项目。

Windows 标题栏与窗口控制使用专用验证命令 `npm run test:window-chrome`，覆盖无边框布局、主页设置入口、最小化、最大化、还原、关闭及窗口隔离；该命令仅在 Windows 执行，在其他系统会跳过。`npm run test:windows` 则是多窗口通用回归，不代表自动启动 Windows 系统测试。

## 常见问题

| 现象                             | 处理方式                                                                                          |
| -------------------------------- | ------------------------------------------------------------------------------------------------- |
| `5173` 被占用，F5 无法继续启动   | 先结束同一项目已有的 `npm run dev` 或检查正在运行的 Vite 任务，再启动。不要同时重复启动开发服务。 |
| 界面附加超时或无法连接 `9222`    | 确认先运行了开发启动配置，且 Electron 没有在主进程断点处停住；确认没有其他应用占用端口。          |
| React 断点没有命中               | 确认选择的是完整调试，或已附加对应界面窗口；独立工作台请选择地址含 `#project` 的目标。            |
| 清理完成但旧调试会话仍存在       | 先停止此前已启动的旧会话，再重新运行当前配置。当前清理配置会在脚本退出后自动结束。                |
| 停止调试后仍有 Vite 终端         | 这是保留的后台任务；在「终端 → 终止任务」中结束「开发：Vite」。                                   |
| 新安装依赖后缺少文件图标或匹配表 | 使用开发启动、`npm run dev:renderer` 或 `npm run build`，它们会自动生成图标资源。                 |

## 新增和调整配置时如何维护

后续配置变更应与本文一起提交，保持菜单名称、执行命令和说明一致：

1. 新增或调整 F5 入口时，更新 `launch.json`；在本文相应分组中说明名称、用途、前置条件、输出位置与结束方式。隐藏辅助配置和组合配置也要记录。
2. 新增或调整任务时，更新 `tasks.json`，并补充「任务菜单一览」。涉及 npm 命令时同步修改 `package.json`；引用的任务标签和组合成员名称必须存在。
3. 开发配置放入 `01 开发调试`，构建和打包放入 `02 构建打包`，清理放入 `03 清理产物`，用 `presentation.order` 排序。仅供组合配置调用的辅助项可以隐藏。
4. 一次性构建、打包和清理应跟随命令进程退出，不改成长期保留 Shell 的 `node-terminal` 会话；需要长期服务时使用明确的后台任务，并说明如何停止。
5. 涉及端口、环境变量、平台差异、清理范围或保存位置时，更新对应说明。改变目录结构时还需更新[项目目录说明](项目目录说明.md)；README 中的入口和摘要也要保持一致。
6. 检查配置引用、文档链接和格式；行为有变化时实际运行相关入口。一次性命令需要确认成功和失败后都能结束，不应为验证清理而删除仍需保留的真实文件。

`docs/` 下的说明文档统一使用中文正文和中文文件名；产品名称、代码标识、命令、版本号等按其原名书写。README 保留中文默认版与英文版。
